# Требования

## User Stories

### US-01. Ввод сообщения

Как пользователь,
я хочу вводить текст сообщения,
чтобы отправить его на проверку наличия спама.

Критерии приёмки:

- в интерфейсе доступно поле для ввода текста;
- введённый текст можно изменить перед проверкой;
- при отправке пустого текста или текста из одних пробелов
  система показывает просьбу ввести сообщение.

### US-02. Проверка сообщения

Как пользователь,
я хочу получать результат классификации сообщения,
чтобы понимать, содержит ли оно спам.

Критерии приёмки:

- проверка запускается нажатием кнопки «Проверить»;
- после успешной обработки отображается один из результатов:
  «Спам» или «Обычное сообщение»;
- при ошибке обработки отображается сообщение
  «Не удалось проверить сообщение. Попробуйте ещё раз».

### US-03. Повторная проверка

Как пользователь,
я хочу проверять другое сообщение без перезагрузки страницы,
чтобы последовательно проверить несколько сообщений.

Критерии приёмки:

- после получения результата поле ввода остаётся доступным
  для редактирования;
- изменённый текст можно отправить на новую проверку;
- при запуске новой проверки предыдущий результат скрывается,
  а после её завершения отображается новый.

## Use Case

### UC-01. Проверка сообщения на спам

Актор: пользователь.

Цель: определить, является ли сообщение спамом.

Предусловие: пользователь открыл страницу сервиса.

Основной сценарий:

1. Пользователь вводит текст сообщения.
2. Пользователь нажимает кнопку «Проверить».
3. Приложение проверяет, что текст не пустой.
4. Приложение передаёт текст ML-модели.
5. ML-модель классифицирует сообщение.
6. Приложение получает результат классификации.
7. Пользователь видит результат «Спам»
   или «Обычное сообщение».

Альтернативные сценарии:

- На шаге 3: если текст пустой или состоит из одних пробелов,
  приложение просит ввести сообщение и не вызывает ML-модель.
- На шаге 5: если модель не смогла обработать сообщение,
  приложение показывает:
  «Не удалось проверить сообщение. Попробуйте ещё раз».

Результат: пользователь получил результат классификации
или сообщение о причине, по которой проверка не выполнена.
